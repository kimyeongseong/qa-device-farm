# 설계 노트

왜 이렇게 만들었는지, 그리고 어디까지만 만들었는지에 대한 기록입니다.

## 출발점

QA를 하면서 실기기가 개인 PC에 물려 있는 구조가 계속 걸렸습니다.

- 기기를 쓰려면 그 기기가 꽂힌 자리로 가야 합니다.
- 누가 지금 뭘 만지는지 알 방법이 없어서, 재현 테스트 중에 남이 앱을 지워버리는 일이 생깁니다.
- 자동화 스크립트를 짜도 그 사람 PC에서만 돕니다.

그래서 목표를 하나로 잡았습니다. **기기를 PC에서 떼어내 네트워크 뒤에 놓고, 브라우저든 스크립트든 같은 API로 접근하게 만들기.**

## 구성

두 개의 프로세스가 돕니다.

| 프로세스 | 포트 | 하는 일 |
|---|---|---|
| `server.py` (FastAPI) | 8001 | 기기 목록, 점유, 입력, APK 설치, 매크로, 스크린샷. 대시보드 정적 파일도 여기서 서빙합니다. |
| `ws-scrcpy` (Node) | 8000 | H.264 저지연 화면 미러링. |

미러링을 직접 만들지 않고 ws-scrcpy를 가져다 쓴 이유는, 화면 전송이 이 프로젝트에서 풀려는 문제가 아니었기 때문입니다. 대신 스트림 기본값(720p·7Mbps·60fps)을 팜 운영에 맞게 고정하는 패치만 얹었습니다 (`NOTICE.md` 참고).

`server.py`에도 `/ws/video/{serial}` 경로로 `adb exec-out screenrecord` 기반 스트림이 있습니다. ws-scrcpy 없이 최소 구성으로 돌릴 때를 위한 폴백이고, 화질·지연 모두 ws-scrcpy 쪽이 낫습니다.

## 왜 세션이 없나

처음에는 Appium을 얹을까 고민했습니다. 그런데 이 팜에서 필요한 건 "탭 한 번, 스크린샷 한 장"이 대부분인데, 그걸 위해 세션을 열고 닫는 비용이 너무 컸습니다.

그래서 조작 하나 = HTTP 요청 하나로 갔습니다. 서버는 요청 사이에 기기에 대한 상태를 들고 있지 않고, 기기 목록조차 adb에서 매번 새로 읽습니다. 대신 상태가 정말 필요한 딱 한 가지 — "지금 누가 이 기기를 쓰는가" — 만 lease로 따로 관리합니다.

토스 Nebula 아티클에서 같은 판단(Appium 세션 제거, stateless HTTP)을 훨씬 큰 규모에서 내린 걸 보고, 이 방향이 맞다고 확인했습니다.

## 점유(Lease)

```
POST /api/devices/occupy   {"owner": "ci-smoke", "ttl_seconds": 300}
  → {"serial": "R3CN30ABCDE", "owner": "ci-smoke", "expires_at": ...}
```

세 가지를 의도했습니다.

1. **TTL이 있습니다.** 반납을 못 하고 죽는 경우가 반드시 생깁니다. CI 잡이 타임아웃되거나, 브라우저 탭이 그냥 닫히거나. 만료 시각을 박아두면 아무도 개입하지 않아도 기기가 돌아옵니다.
2. **"아무거나 하나" 요청이 가능합니다.** 파이프라인은 보통 특정 기기가 아니라 그냥 안드로이드 한 대가 필요합니다. `/api/devices/occupy`가 유휴 기기를 골라 시리얼을 돌려줍니다.
3. **강제 범위를 나눴습니다.** HTTP 입력 API(`/api/device/{serial}/input`)는 lease를 강제해서 CI끼리 충돌하지 않게 합니다. 반면 브라우저의 WebSocket 조작은 막지 않고 대시보드에 점유자만 표시합니다. 사람이 급하게 확인해야 하는 상황에서 락에 막히는 게 더 나쁘다고 봤습니다.

메모리에만 저장하므로 서버 재시작 시 전부 사라집니다. 기기 수십 대 규모에서는 재시작이 드물고, 만료 기기를 정리해주는 이점이 더 큽니다. 규모가 커지면 Redis 같은 외부 저장소로 옮겨야 합니다.

## 입력 주입

좌표는 브라우저와 CI 양쪽에서 들어옵니다. 초기 버전은 이랬습니다.

```python
cmd = f'"{adb_path}" -s {serial} shell input tap {x} {y}'
await asyncio.create_subprocess_shell(cmd)
```

`x`가 검증 없이 셸 문자열에 들어갑니다. 인증이 없는 서버에서 이건 그대로 원격 명령 실행입니다. 지금은 정수로 파싱한 뒤 argv로 넘깁니다.

```python
x, y = as_int(event.get("x"), "x"), as_int(event.get("y"), "y")
await adb_exec(adb_path, serial, "shell", "input", "tap", str(x), str(y))
```

APK 업로드도 같은 문제가 있었습니다. 파일 이름이 셸 문자열에 그대로 들어가서, `basename` 처리 후 argv로 넘기도록 바꿨습니다.

이벤트 해석은 `dispatch_input()` 한 곳에 모았습니다. WebSocket 조작, 매크로 재생, HTTP 입력 API가 전부 이 함수를 지나갑니다 — 검증을 세 군데에 복사하면 언젠가 한 군데가 빠집니다.

## 스크린샷 직렬화

같은 기기에 스크린샷 요청이 동시에 들어가면 adb가 자주 깨집니다. 대시보드가 여러 기기를 폴링하면 바로 재현됩니다.

기기별 `asyncio.Lock`으로 한 번에 하나만 통과시키고, 캡처 자체는 블로킹이라 스레드 풀에서 돌립니다. 두 번 재시도해도 실패하면 예외를 올리지 않고 `503`을 반환합니다 — 프론트가 조용히 다시 시도하면 되고, 기기 한 대의 실패가 대시보드 전체를 흔들 이유가 없습니다.

## 만들지 않은 것

이 프로젝트가 다루지 않는 범위입니다.

- **iOS.** USB 독점 문제와 캡처 장치 처리가 필요한데, 안드로이드 실기기 공유라는 원래 목적에서 벗어납니다.
- **에이전트 계층.** 호스트 PC 한 대에 물린 기기만 관리합니다. 호스트가 여러 대로 늘어나면 호스트마다 에이전트를 두고 중앙에서 오케스트레이션하는 구조가 필요합니다.
- **자체 드라이버.** `adb shell input`을 그대로 씁니다. 호출당 수백 ms가 들어서 고빈도 조작에는 느립니다. 더 빠르게 하려면 기기 안에 상주 컨트롤러를 올려야 합니다.
- **인증.** 신뢰된 네트워크를 전제합니다. 공개 노출은 터널 앞단에서 인증을 처리해야 합니다.
- **한글 IME.** `adb shell input text`가 ASCII만 받습니다. 한글·이모지 입력은 기기에 별도 IME를 설치해야 합니다.
